Routing Architecture

Complete BGP, EVPN/VXLAN, route-policy, and prefix-list documentation derived from live configs and the YAML spec.

Design Overview

The entire network uses BGP exclusively — no OSPF, no static routes. The design splits into underlay (eBGP point-to-point) and overlay (iBGP EVPN via loopbacks). Each leaf has a unique ASN; spines share AS 65000 and act as route reflectors for the EVPN overlay.

    (AS 65001-65004)                   Route Reflectors

                      │
               VXLAN Data Plane
              (VTEP on Loopback1)

    CE Routers (AS 65100) ── eBGP ── SP PEs (AS 64500)
       dual-homed via PRIMARY/SECONDARY route-maps

Border Leaf Route Filtering

dc-border-1 and dc-border-2 use prefix-lists and route-maps to control which routes are redistributed from connected into BGP. Only DC fabric and server subnets are advertised outbound.

! Applied on dc-border-1 and dc-border-2

ip prefix-list DC-SUMMARIES seq 10 permit 10.1.0.0/16 le 32
ip prefix-list DC-SUMMARIES seq 20 permit 10.10.0.0/16 le 32

route-map ADVERTISE-DC permit 10
   match ip address prefix-list DC-SUMMARIES

router bgp {{ asn }}
   redistribute connected route-map ADVERTISE-DC
i
Design intent: Only DC infrastructure (10.1.0.0/16) and server subnets (10.10.0.0/16) leak outward from the fabric. Transit and WAN prefixes are excluded from redistribution.

Key Routing Design Patterns

  • Underlay/Overlay split: eBGP /31 P2P for underlay reachability, separate loopback-based EVPN overlay for MAC/IP advertisement
  • Per-leaf ASN: Each leaf gets a unique ASN (65001-65004, 65201-65202) enabling eBGP underlay without iBGP full-mesh
  • Anycast gateways: All leaves share virtual MAC 00:1c:73:00:00:01 — hosts use the same default gateway regardless of which leaf they attach to
  • Collapsed DR: DR site skips the spine layer — two leaves peer directly, reducing resource usage while maintaining EVPN capability
  • Dual-homed CEs: Primary/secondary PE selection via route-map local-preference (200 vs 100) — deterministic failover, not random
  • Border route filtering: Only DC summaries (/16s) are redistributed outward via prefix-list match — prevents transit leaks
  • Cross-site RT sharing: VNI 10100 uses route-target 65000:10100 on both DC and DR — enables L2 extension across sites when WAN path is available
  • No OSPF, no static routes: Pure BGP everywhere — one protocol to monitor, one set of show commands, one failure domain per session

Troubleshooting Runbook

21 confirmed gotchas from this build, organized by category and severity. Every entry here was hit in production.

EVE-NG Platform

CRITICAL #1 — Config parameter causes boot death ▶

Symptom

Device fails to boot after API creation.

Root Cause

Config param must be "0" or "1". Setting to base64/text/"none" kills the node.

Fix

  • Always "config": "0". Startup configs injected as files.
HIGH #2 — EVE-NG Pro API paths need .unl extension ▶

Fix

  • Include .unl in paths: /api/v2/labs/AI-Infra-Lab.unl/nodes
  • Include leading /
HIGH #3 — EVE-NG Pro stop API returns 400 ▶

Workaround

  • Use web UI to stop, or call start on running node (restarts it)
HIGH #4 — C8000v needs 4 CPU / 8GB RAM minimum ▶

Required

  • cpu=4, ram=8192, ethernet=6. Gi5 = management. 5 nodes = 20 vCPUs + 40GB.
MEDIUM #5 — Alpine Linux uses e0/e1, not eth0/eth1 ▶

Fix

  • Use e0/e1 in all Alpine configs. Verify with ip link show.

FortiGate Specific

HIGH #6 — No startup-config injection for FortiGate / Alpine ▶

Fix

  • Configure management via console on first boot. One-time step.
CRITICAL #7 — Pushing HA config via SSH kills the session ▶

Fix

  • HA config via console only. Push script must skip config system ha block.
CRITICAL #8 — Standby FortiGate data ports show 0.0.0.0 ▶

This is normal.

Only active unit holds data IPs. Skip data-plane IP checks on standby.

CRITICAL #9 — HA heartbeat not cabled — both units go standalone ▶

HIGH #10 — HA negotiation steals management IP ▶

Fix

  • Configure ha-mgmt-status enable + ha-mgmt-interfaces BEFORE enabling HA mode.
HIGH #11 — FortiGate Netmiko driver quirks ▶

Settings

  • device_type='fortinet', timeout=30, use write_channel, never call enable()

Debug

Both borders need prefix-list DC-SUMMARIES (10.1.0.0/16 le 32, 10.10.0.0/16 le 32) and route-map ADVERTISE-DC matching it on redistribute connected.

VXLAN / EVPN Data Plane

CRITICAL VXLAN tunnel down — VTEPs can't reach each other ▶

Debug

  • show vxlan vtep, ping <vtep> source lo1, show interface vxlan1

Common Causes

  • Loopback1 not advertised in eBGP

  • MTU too low (VXLAN adds 50 bytes)

Fix

  • VNI 10100 → same VLAN on all leaves

FortiGate HA Compound Failures

CRITICAL #21 — FortiGate HA cascade: heartbeat + ha-mgmt + DHCP mode ▶

Three compounding issues:

  1. port3 heartbeat not cabled → HA never forms
  2. ha-mgmt-status not active → standby loses management
  3. set mode static missing → IPs silently ignored

Fix

  • Cable heartbeat (port3)
  • Add ha-mgmt-status to HA config
  • Add set mode static before all set ip commands
